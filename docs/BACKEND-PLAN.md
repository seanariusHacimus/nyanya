# План: полный бэкенд для nyanya-app (без платежей)

Дата: 2026-07-27 · Статус: согласовывается

## Целевая модель

Одно приложение `nyanya-app` (текущий фронтенд) получает собственный бэкенд на
встроенных серверных механизмах Next.js — **отдельный сервис не нужен**:

- **PostgreSQL** — уже существующий сервис Postgres в Railway-проекте
  `imaginative-courtesy`; локально — docker-compose (Postgres, порт 5434).
- **Drizzle ORM** — переносим и адаптируем готовую схему старого приложения
  (`src/db/schema.ts` + `auth-schema.ts` на ветке main): users/roles,
  specialists, documents, reviews, favorites, unlocks, notifications.
- **Better Auth** — сессии и роли (parent · specialist · admin), плагин
  **email-OTP**: при регистрации и входе на почту приходит код подтверждения.
  Телефон собираем в профиле как обязательное поле; SMS-подтверждение (Eskiz)
  подключается позже тем же интерфейсом провайдера — mock-first, как задумано
  в старом приложении.
- **Server Actions** — вся мутация данных (паттерн старого приложения:
  Zod-валидация + проверка сессии/роли/владения).
- **Без платежей.** Всё бесплатно: открытие контактов — по кнопке после входа.
  Таблицу unlocks сохраняем (метрики воронки + уведомление специалисту +
  лёгкий возврат монетизации позже), таблицы платежей не используем.

## Что уходит в БД, что остаётся в коде

| В PostgreSQL | Остаётся в коде (статика) |
|---|---|
| Пользователи, роли, сессии | Тексты страниц (девиз, разделы, FAQ) |
| Анкеты специалистов (12 текущих — сид) | Статьи блога (маркетинг; в БД — опц. фазой 10) |
| Отзывы, избранное, открытия контактов | Дизайн-токены |
| Документы верификации + статусы | Юридические тексты |
| Уведомления | |

## Фазы

**Ф1. Фундамент** — docker-compose для локального Postgres; перенос drizzle-схемы
из старого приложения в nyanya-app (минус платёжные поля, плюс правки под новый
фронт); миграции; сид-скрипт: 12 анкет + отзывы + демо-админ.

**Ф2. Аутентификация** — Better Auth + email-OTP (Resend или SMTP через env;
в dev код печатается в консоль — без внешних зависимостей). Экраны /login,
/register, /verify-phone → реальные (verify-код с почты). Middleware-защита
/account, /specialist, /admin по ролям. Redirect-back (§9 R4) сохраняем.

**Ф3. Каталог и профили из БД** — страницы каталога/профиля читают Postgres
(RSC); фильтры, сортировка, «похожие», отзывы — из данных; monogram-fallback
для анкет без фото.

**Ф4. Бесплатное открытие контактов** — модал оплаты убирается; кнопка
«Открыть контакты» (после входа) пишет unlock и показывает контакты; специалисту
уходит уведомление. Чистка копии по всему сайту: цены 29 000 сум, раздел
«Оплата» в FAQ, «Что происходит после оплаты» (→ «после открытия»), шаг 03
на главной, terms §6, панель профиля. Реестр правок — в этой же фазе.

**Ф5. Кабинет заказчика** — избранное, открытые контакты, уведомления из БД;
настройки (смена пароля, язык).

**Ф6. Кабинет специалиста** — анкета CRUD с автосейвом → статус-машина
модерации по-настоящему (draft → review → published/rejected с причиной);
загрузка документов в хранилище (Railway volume для MVP, интерфейс позволяет
переехать на S3/R2); повторная модерация правок (D27).

**Ф7. Админка** — доступ только роли admin; статистика из БД; модерация анкет
(publish/hide/reject+причина); очередь проверки документов; блокировка
пользователей (блокированный получает отказ на входе — §9 R1).

**Ф8. Уведомления и системные состояния** — in-app уведомления по событиям
(контакты открыты, статус анкеты, документ проверен); тосты; skeleton-лоадеры.

**Ф9. Деплой и приёмка** — миграции на Railway Postgres (DATABASE_URL из
сервиса в том же проекте); env-переменные; e2e-прогон обеих воронок на проде;
мультиагентное ревью (безопасность actions: роли/владение/IDOR — обязательный
пункт); обновление PR.

**Ф10 (опция, после MVP)** — блог в БД + админ-редактор; SMS-подтверждение
через Eskiz; возврат платежей за открытие контактов фичефлагом.

## Что нужно от владельца

1. **Почтовый провайдер для OTP**: ключ Resend (рекомендую, 100 писем/день
   бесплатно) или SMTP-доступ. До получения ключа — dev-mock (код в консоль).
2. Подтвердить: контакты специалистов открываются бесплатно, но **только после
   входа** (сохраняет ценность регистрации и уведомления специалистам).
3. Подтвердить судьбу демо-режима: localStorage-демо полностью заменяется
   реальным бэкендом.

## Порядок работы

Фазы идут последовательно, каждая заканчивается рабочим состоянием на проде
(деплой после Ф2, Ф4, Ф7, Ф9 — промежуточные точки, где сайт остаётся целым).
